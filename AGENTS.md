# AGENTS.md

## Project Rules — apply to every subtask in this session

- **Repo:** servicedesk-ai. Telnyx Edge (`telnyx.toml` umbrella manifest), TypeScript strict, Vitest.
- **One subtask = one prompt = one check.** Stay inside the allowed scope. If something outside it must change, stop and report instead of changing it.
- **Do NOT deploy** (`telnyx-edge ship`), do NOT write to remote KV, do NOT read or print secrets or `.env`.
- **Do NOT edit `telnyx-env.d.ts` by hand.** It is generated by `telnyx-edge types`.
- **No new dependencies** unless the subtask explicitly allows one (pin exact versions).
- **Preserve behavior** unless the subtask explicitly changes it. Keep fail-closed semantics: infra failures → `503` with a generic body, never raw error messages.
- **Never log, return, or snapshot** `customer_name` / `customer_phone` values.
- **Comments explain WHY.** No "Step 1..N" narration, no subtask IDs in code comments.
- **Closing evidence for every subtask:** `npm run typecheck` (0 errors), `npm test` (all passing, report the count), list of changed files, and an explicit list of behavior changes (or "none").

## Safe Commands

```bash
npm install          # install dependencies
npm run typecheck    # tsc --noEmit (strict mode)
npm run test         # vitest run (full suite)
npm run dev          # telnyx-edge dev (local runtime; needs Docker)
telnyx-edge types    # regenerate telnyx-env.d.ts from manifest
```

## Project Structure

- `telnyx.toml` — umbrella manifest (actors, KV, secrets bindings)
- `telnyx-env.d.ts` — generated types (DO NOT EDIT)
- `src/index.ts` — fetch handler entrypoint, route dispatch
- `src/config.ts` — KV config loader with runtime validation
- `src/scheduling.ts` — pure scheduling domain (dates, slots, timezone, window)
- `src/agenda-actor.ts` — `DayAgenda` StatefulActor (occupancy read + booking write)
- `src/availability.ts` — availability service (scheduling + Actor occupancy)
- `src/bookings.ts` — HTTP booking adapter (body limits, structural validation, Actor routing)
- `src/counter.ts` — demo Counter actor (platform probe)
- `config/main.json` — non-sensitive demo seed configuration
- `test/` — Vitest test suite (all mocked; no real runtime)
- `docs/` — architecture, verification, debugging, booking-domain spec
- `scripts/` — remote verification scripts

## Key Contracts

- **Health** (`GET /health`) is public, no auth.
- **Demo routes** (`/demo/*`) are auth-gated by `SMOKE_AUTH` (`SMOKE_TEST_TOKEN`).
- **KV** holds config only; never transactional booking state.
- **Actor** (`DayAgenda`) owns authoritative occupancy + idempotency per location/day.
- **booking_enabled** is an admission flag; replays bypass it ([C6]).
- **fail-closed:** infra failures → `503 { error: "service_unavailable" }`.
- **Timezone:** `America/Mexico_City` always; never use browser/process TZ.
